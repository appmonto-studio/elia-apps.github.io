# The website in the Elia ecosystem

This document explains where this repository sits relative to the rest of Elia,
and — just as importantly — what it deliberately does not do.

## Role of this repository

This repository is the **public presentation layer of the Elia ecosystem**: the
marketing and application-information site served at <https://getelia.app>. It
is a static site — hand-written HTML, CSS, and a small amount of JavaScript,
generated by `tools/generate_i18n.py` and published through GitHub Pages.

Its job is to explain what the Elia applications are, who they are for, and how
they treat people's data, and to host the privacy and support pages that the app
stores link to. That is the whole scope.

## What this site is not

The website is **not an Elia Platform client**. It has:

- no Elia Account login and no authenticated user area;
- no access to user, family, child, or synchronized application data;
- no Premium, billing, or entitlement management;
- no synchronization or cloud data access;
- no family dashboard;
- no backend of any kind.

The site handles **no private family data**. Everything it serves is public
marketing copy and static assets. There is no database, no session, no form that
collects personal data, and no analytics.

There is **no current runtime dependency on Elia Platform.**

## Where the rest of Elia lives

| Part of the ecosystem | Where it lives |
| --- | --- |
| Elia Contractions | Private application repository |
| Elia Feeding | Private application repository |
| Elia Moments | Private application repository |
| Elia Platform | Private shared platform repository |
| Elia Foundation | Private shared product-philosophy repository |

Application implementation lives in the private application repositories. Shared
account, family, Premium, synchronization, cloud, and security architecture
lives in the private Elia Platform repository. Neither is described in detail
here, and neither is a dependency of this site.

Shared product philosophy — product principles, voice and copy rules, medical
boundaries, trust and data philosophy — lives in the private Elia Foundation
repository. That one **does** govern this site: the copy published here follows
the same voice and the same medical boundary as the applications. See the *Voice
and medical boundary* section of [`CLAUDE.md`](../CLAUDE.md).

## Documentation ownership

Keeping these boundaries clear prevents the same decision being recorded in two
places with two different answers.

| Concern | Owned by |
| --- | --- |
| Marketing copy, page structure, site design, localization | This repository |
| Application domain logic, data model, business rules, app-specific privacy behavior | The individual application repositories |
| Account, family, child, Premium, entitlements, synchronization, media infrastructure, cloud and security architecture | The Elia Platform repository |

Consequences worth stating plainly:

- **Application behavior is described here, never defined here.** When a page
  says what an app does, the application repository is the source of truth. If
  the two disagree, the app repository wins and the site copy is the bug.
- **Platform concepts are not modelled here.** This repository defines no data
  scopes, no synchronization entities, and no backend architecture.
- **Privacy pages on this site are a published copy of each app's policy.** They
  must be updated together with the application repository, never independently.

## Possible future capabilities — not approved, not planned

Nothing in this section is a commitment or a roadmap item. It is recorded only so
that nobody mistakes the current boundary for an oversight.

A platform-facing web client — anything involving Elia Account login, family
invitation acceptance, account or billing management, cloud data access, or a
family dashboard — **is not approved and is not planned.** Building any of it
would turn this static public site into a system that processes personal data,
and it would require a separate product and architecture decision taken
deliberately, with its own privacy and security review.

Until such a decision exists, treat this repository as a public static site and
nothing more.
